# Изолированные физические испытания Whisper

Каждую сравниваемую версию публиковать на самостоятельном HTTPS-origin, отдельно
от production и других контрольных версий. Разные пути одного origin не изолируют
localStorage профилей/контактов.

Для Android испытаний доступ должен быть публичным по ссылке без обязательной
авторизации OpenAI/ChatGPT. Owner-only preview и private bypass ссылки не считаются
пригодной публикацией. Настроить audience public и проверить конечный URL в новом
браузерном контексте без cookies/Authorization/bypass tokens. Не применять токены
для обхода проверки. Если GET блокируется средой, отметить anonymous verification
BLOCKED и не выдавать access-policy metadata за выполненную проверку телефона.

На сайте явно показывать название, build ID и исходный runtime commit. Сохранять
отдельный manifest файлов и SHA-256. Пассивная диагностика не должна менять
signaling/STUN/TURN, guards, сроки, reconnect/recovery или пользовательское хранилище.

Безопасный экспорт должен содержать только allowlisted состояния, времена,
счётчики и локальные технические метки экземпляров. Не включать raw SDP/ICE,
адреса/IP, profile/peer/session IDs, ключи, TURN credentials, cookie/token/URLfragment
и содержимое сообщений. Обычный подробный лог приложения не считать автоматически
безопасным экспортом. Диагностические ошибки экспортировать только как тип/счётчик.

Раздельно отчитываться: модельные проверки, настоящий localhost WebSocket,
удалённый production signaling, настоящий WebRTC и физические Android. Для
невыполненных проверок писать NOT RUN, для ограничения проверки — BLOCKED.

Отсутствие лога WebSocket open не доказывает отсутствие нативного события.
Сравнивать native readyState/open, обработку приложением, ownership, Join,
signaling-ready и presence перед диагностикой ICE.

Если причина дефекта не установлена, не публиковать диагностическую копию под
названием «исправленная». Сохранять контрольные исходники и продолжать сбор фактов.

Тестовые профили создавать заново на каждом origin. Общий signaling не разделяется
по origin; не импортировать рабочие идентификаторы. Добавлять только нужные
тестовые контакты. Публикация теста не разрешает Merge или production rollout.
