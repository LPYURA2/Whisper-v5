# Возврат Whisper v5 к принятой версии до ExpressTURN

Исходный commit: 9657faaaa59c31d3b3c2c489fc9a20a61e6fe5b0.
GitHub backup ref: backup/pre-expressturn-20261030-9657faaa.
Рабочий сайт: https://lpyura2.github.io/Whisper-v5/.
Pages: main, /(root), публикация при изменении main.

Никакой откат этим документом не выполняется. Перед откатом проверить текущий
main, опубликованный deployment, diff и наличие последующих изменений.

1. Проверить CHECKSUMS.txt и целостность CLIENT-SOURCE.zip/HISTORY.bundle.
2. git clone HISTORY.bundle recovered-whisper
3. В новой локальной ветке от актуального origin/main подготовить отмену
   исключительно production PR ExpressTURN через git revert соответствующего
   merge commit (-m 1), либо соответствующего squash commit без -m 1.
   Сначала определить фактический способ объединения и SHA. Если после выпуска
   были другие изменения, разобрать конфликты и diff; не восстанавливать весь
   старый tree поверх неизвестных изменений.
4. Убедиться, что восстановлен прежний RTCManager, а профили, storage и все
   остальные согласованные файлы не затронуты. Проверить синтаксис/регрессии.
5. Создать отдельный rollback PR; объединять только по решению владельца.
   Force push/reset main и очистка localStorage не нужны.
6. Проверить успешный Pages run и сравнить опубликованные assets с rollback
   artifact. Если возвращается точно исходная версия, сверить SHA-256 каждого
   файла из MANIFEST.json. Более поздние изменения учитывать отдельно.

Архив восстанавливает исходники подтверждённого commit. GitHub Pages log
связывает последний успешный deployment с этим commit. Текущие live HTTP bytes
не получены из-за proxy403; старый Pages artifact недоступен (GitHub404).
Эта оговорка не должна теряться при передаче резервной копии.

Исходники не содержат пользовательские профили и переписку из localStorage
телефонов. Обновление и откат кода не должны очищать пользовательское хранилище.
